# Contributing to Fragment

Fragment is an early-stage open-source product workspace by Lilac Fragment. We welcome contributions that make the product clearer, calmer, and more useful.

## Before you start

- Read the [README](README.md) and [roadmap](docs/roadmap.md).
- Open an issue to discuss any non-trivial change before you write code.
- Keep PRs focused — one feature or fix per PR.

## Contribution areas

- UI components
- Spec templates
- Prompt workflows
- Product documentation
- Export formats
- Integrations
- Accessibility
- Testing
- Example workflows
- Design system
- Developer experience

## Contribution principles

Contributions should:

- Improve clarity
- Reduce ambiguity
- Respect the product direction
- Keep the UI calm and usable
- Avoid unnecessary complexity
- Be documented
- Be reviewable

## Good first issues

- Improve the README
- Add sample spec templates
- Improve empty-state copy
- Improve landing-page accessibility
- Add a Markdown export example
- Create issue templates
- Add design tokens
- Add keyboard focus states
- Add sample product context files

## Workflow

1. Fork the repo and create a feature branch.
2. Run `npm install`.
3. Run `npm run typecheck` before opening a PR.
4. Use [Conventional Commits](https://www.conventionalcommits.org/) for messages (`feat:`, `fix:`, `docs:`, `refactor:`).
5. Open a PR with a short description of what changed and why.

## Maintainer role

The primary maintainer is responsible for:

- Product direction
- Issue triage
- Roadmap decisions
- Pull request review
- Documentation quality
- Release planning
- Community standards
